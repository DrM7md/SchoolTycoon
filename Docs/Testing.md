## الأوامر

من جذر المستودع:

```bash
dotnet run --project tests/SchoolDirectorTycoon.Tests -c Release -m:1
dotnet build -c Release -m:1 -p:UseSharedCompilation=false
dotnet run --project tests/SchoolDirectorTycoon.Tests.NetStandard -c Release --no-build
dotnet run --project tests/SchoolDirectorTycoon.Desktop.Tests -c Release --no-build
powershell -ExecutionPolicy Bypass -File tools/CopyCoreToUnity.ps1
```

اختبارات EditMode في Unity (عدّل مسار المشروع):

```bash
"C:\Program Files\Unity\Hub\Editor\6000.0.85f2\Editor\Unity.exe" -batchmode -nographics -projectPath <Unity/SchoolDirectorTycoon> -runTests -testPlatform EditMode -testResults edit.xml -logFile edit.log
```

**العام الآلي:** ابنِ المشهد بـ`ChronicleSceneBuilder.BuildFromCommandLine` ثم نسخة Windows بـ`ChronicleSceneBuilder.Windows -buildPath <مجلد>`. شغّل النسخة بالمعاملات `-sdtLang ar` (ثم `en`) و`-sdtChronicle <ملف التقرير> <صورة.png>`. يلعب `LifeDevTest` عامًا كاملًا عبر الأزرار الحقيقية، ويكتب سطر PASS أو FAIL لكل خطوة، ويحفظ صورة لكل شاشة باسم `shot-{ar|en}-*.png`. النجاح يعني `failures=0` و`ending=YearCompleted day=180` في اللغتين.

**تحذير:** لا تشغّل نسخة أخرى من اللعبة أثناء العام الآلي. في 2026-11-09 أبطأ ذلك الإطارات فانتهت المهلة (1000 ثانية) وفشلت فحوص الرسائل المنبثقة الموقوتة، مع أن الكود سليم. الجولة النظيفة تستغرق نحو 280 ثانية لكل لغة.

## لم يُختبر بعد

- هاتف حقيقي، وبناء IL2CPP، وAndroid وiOS. كل ما سبق على Windows Mono للتطوير.
- لعب كامل عبر الأزرار لسيناريوهات الإنقاذ والبنات والدولي والقرية. هي مختبرة في النواة فقط، والقرية فُحصت في شاشة التأسيس.
- ترقية الوكيل، ورفض ترقية معلم غير مؤهل.
- زر قرار لا يكفي المال لدفعه (`disabledAnswers=0` في كل الجولات).
- التحدي الأسبوعي بأيام حقيقية؛ الاختبار يستخدم يومًا مصطنعًا.
- قراءة حفظ الإصدار 1 داخل Unity؛ مختبرة في النواة فقط.

## عيوب معروفة

- قد تنزل نقطة وحدها في آخر سطر ملفوف.
- احتفال ارتقاء المستوى يُفقد إذا أُغلقت اللعبة قبل عرضه، والخبرة نفسها محفوظة.
- بوت العام الآلي يختار إجابات فاسدة حتى تقع الفضيحة، فنتيجته ليست مقياسًا للتوازن.
